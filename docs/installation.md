# Installing Rellin

Rellin requires Node.js 22.6 or newer and a real terminal. Install and sign in
to the agent CLIs you want to use separately. Installing Rellin does not install
provider accounts, transfer credentials, or copy conversations between machines.

## Install from npm

Install or update with:

```powershell
npm install -g rellin
rellin
```

The package name is `rellin`. npm selects its `latest` tag by default;
`npm install -g rellin@latest` is the explicit equivalent. A `-latest` suffix
would be a different package name. End users do not need an npm account to
install a public package. GitHub Release archives remain an alternative below.

## Install from a GitHub Release

Once a release contains an asset named `rellin.tgz`, npm can download and install
it in one command:

```powershell
npm install -g https://github.com/Lueken/rellin/releases/latest/download/rellin.tgz
rellin
```

For a specific release, use its tag instead of `latest`:

```powershell
npm install -g https://github.com/Lueken/rellin/releases/download/v0.6.0/rellin.tgz
```

These commands require the release asset to have been published. A source-code
ZIP generated by GitHub is not the npm package. Release installs are snapshots;
repeat the install command to update. Downloads need internet access for the
archive and dependencies. Private repositories require authenticated downloads;
the direct public URL does not use a browser's GitHub login.

The terminal dependency `node-pty` contains native code. Keep dependency install
scripts enabled; platforms without a compatible prebuilt binary need its native
build toolchain. On Windows that can include Python and Visual Studio C++ Build
Tools. Installation from a release does not require Git.

## Work from source

```powershell
git clone https://github.com/Lueken/rellin.git
cd rellin
npm ci
npm link
rellin
```

If replacing an existing `station` launcher, `npm link --force` replaces that
launcher as well. `rellin` is the official command; `station` remains a
compatibility alias. Linked source changes apply on the next launch, with no
build step. `npm start` also runs the current checkout.

## Package a release

Run tests, then create the npm archive:

```powershell
npm test
npm pack
```

For version 0.6.0 the result is `rellin-0.6.0.tgz`. Upload that archive to the
matching GitHub Release as `rellin.tgz` to keep the latest-release URL stable.
The package allowlist contains runtime JavaScript, the README, and installation
and recording documentation. Tests, private development notes, captures, local
databases, and credentials are excluded.

## Publish to npm

Maintainers sign in with `npm login --registry=https://registry.npmjs.org`,
complete npm's authentication requirements, and publish the reviewed archive:

```powershell
npm publish ./rellin-0.6.0.tgz --access public --tag latest
```

The first npm publication requires an available package name. Future releases
must increment the version in both `package.json` and `package-lock.json` before
packing; published name/version combinations cannot be reused. Publishing a
GitHub Release alone does not update npm. The package's `publishConfig` targets
the public npm registry and `latest` tag explicitly.

## Existing Station installations

The rename preserves the legacy `~/.mrmak` data directory, `station.db`, settings
filenames, native conversation identities, and saved request signatures. No
session migration or agent restart is performed by installing a package.
`RELLIN_HOME` selects an alternative data directory; the older `STATION_HOME`
variable remains supported, with `RELLIN_HOME` taking precedence.

The checkout folder may still be named `station`; the package and command do not
depend on that folder name. Renaming a folder used by a live agent can invalidate
its working directory, so move local checkouts only after their sessions close.
